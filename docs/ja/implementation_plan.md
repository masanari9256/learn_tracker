以下は、StudyTracker Proのステップバイステップの実装計画です。各ステップは、必要に応じてソースドキュメントを引用し、正確なファイルの場所とツールを参照しています。

フェーズ1：環境セットアップ

1.  ステップ1：プロジェクトのルートフォルダ `StudyTrackerPro/` とGitリポジトリを作成し、`main`と`dev`の2つのブランチを設定します。

    *   参照：PRDセクション1（プロジェクト概要）
    *   アクション：ターミナルで以下を実行：• mkdir StudyTrackerPro • cd StudyTrackerPro • git init • git checkout -b main • git checkout -b dev
    *   検証：`git branch`を実行してブランチの作成を確認します。

2.  ステップ2：Node.js（Next.js 14をサポートする互換性のあるバージョン）をインストールし、インストールを確認します。

    *   参照：技術スタック（Next.js 14の要件）およびPRDセクション5（技術スタックとツール）
    *   アクション：`node -v`と`npm -v`を実行してバージョンを確認します。（特定のNode.jsバージョンは指定されていませんが、Next.js 14との互換性を確保してください。）

3.  ステップ3：プロジェクトのルートに`.env`ファイルを作成し、Supabase APIキーとStripeキーのプレースホルダーを設定します。

    *   ファイル：`/StudyTrackerPro/.env`
    *   参照：PRDセクション7（制約と前提条件）およびQ&A（Stripe統合のセキュリティ）
    *   検証：`.env`を開き、SUPABASE_URL、SUPABASE_KEY、STRIPE_SECRET_KEYなどのプレースホルダーが存在することを確認します。

4.  ステップ4：開発ツールとしてCursorとLovableをインストールし設定します。

    *   参照：技術スタックと選択されたツール
    *   アクション：Cursorのドキュメントに従って、プロジェクトのルートに`.cursorrules`などの設定ファイルを追加します。

フェーズ2：フロントエンド開発

1.  ステップ5：`/frontend`ディレクトリにTypeScriptを使用してNext.js 14プロジェクトを初期化します。

    *   ファイル：`/StudyTrackerPro/frontend/`
    *   アクション：`/StudyTrackerPro`ディレクトリで`npx create-next-app@14 --typescript`を実行し、生成されたファイルを`/frontend`に移動します。
    *   参照：PRDセクション5（技術スタックとツール）およびアウトライン（tech_stack）
    *   検証：`/frontend`で`npm run dev`を実行し、スターターページがブラウザで読み込まれることを確認します。

2.  ステップ6：フロントエンドプロジェクトにTailwind CSS、shadcn/UI、Radix UI、Lucide Iconsをインストールします。

    *   参照：技術スタックセクション（フロントエンドフレームワーク）
    *   アクション：各ツールのインストールガイドに従って`/frontend`でセットアップと設定を行います（例：`tailwind.config.js`の更新、`/frontend/package.json`にUIライブラリを追加）。
    *   検証：レンダリングされたコンポーネントでスタイリングとアイコンが読み込まれることを確認します。

3.  ステップ7：Supabase認証を使用してセキュアなログインページを開発します。

    *   ファイル：`/frontend/pages/login.tsx`
    *   参照：PRDセクション3（ユーザーフロー）およびコア機能（ユーザー認証とロール管理）
    *   アクション：Supabaseのクライアントライブラリを使用して、メール/パスワードとソーシャルログインをサポートするログインフォームを実装します。
    *   検証：サインアップとログインで認証フローをテストし、認証されたルートへのアクセスを確認します。

4.  ステップ8：マークダウンエディタを備えた日々の学習入力ページを作成します。

    *   ファイル：`/frontend/pages/daily-entry.tsx`
    *   アクション：マークダウンエディタライブラリ（例：react-markdownまたは類似のパッケージ）を統合し、ユーザーがマークダウンで日々の学習ログを記録できるようにします。
    *   参照：PRDセクション1および4（コア機能 – 日々の学習入力）
    *   検証：サンプルのマークダウンコンテンツを入力し、エントリーを保存し、適切なフォーマットでプレビューされることを確認します。

5.  ステップ9：リアルタイムのチャートとグラフを表示するダッシュボードページを構築します。

    *   ファイル：`/frontend/pages/dashboard.tsx`
    *   アクション：学習の進捗を視覚化するためにチャートライブラリ（例：Chart.js）を使用します。デザインガイドライン（明確なナビゲーションを備えたクリーンでミニマルなUI）に従って、明確なナビゲーションとレスポンシブデザインを組み込みます。
    *   参照：PRDセクション4（リアルタイムダッシュボードと分析）
    *   検証：ダミーデータを投入し、チャートがリアルタイムでレンダリングされ更新されることを確認します。

6.  ステップ10：Stripe統合を備えた支払いとサブスクリプションページを開発します。

    *   ファイル：`/frontend/pages/subscription.tsx`
    *   アクション：ユーザーが段階的なサブスクリプションを管理できるページを作成します。サブスクリプションの作成とステータスチェックのためのStripe APIコールを統合します。
    *   参照：PRDセクション4（Stripeを介した支払い統合）およびQ&A（サブスクリプションモデルの詳細）
    *   検証：テスト取引を実行し、サブスクリプションステータスに応じてUIが更新されることを確認します。

7.  ステップ11：英語、スペイン語、フランス語、中国語などの主要言語のローカライゼーションサポート（i18n）を実装します。

    *   ファイル：`/frontend/i18n.config.js`（または選択したi18nライブラリに基づく類似の設定ファイル）
    *   参照：PRDセクション4（ローカライゼーションサポート）およびQ&A
    *   検証：言語設定を変更し、UIに翻訳が適切に表示されることを確認します。

フェーズ3：バックエンド開発

1.  ステップ12：バックエンドサービス（データベース、認証、ストレージ）用のSupabaseプロジェクトをセットアップします。

    *   参照：PRDセクション5（バックエンドとストレージ）および技術スタック（Supabase）
    *   アクション：Supabaseにログインし、新しいプロジェクトを作成し、API認証情報を取得します。ユーザー、日々の学習エントリー、レポート、サブスクリプション用のテーブルでデータベースを設定します。
    *   検証：Supabaseダッシュボードを使用して、テーブルと認証設定が正しく配置されていることを確認します。

2.  ステップ13：ロールベースのアクセス制御（RBAC）を備えたSupabase認証を設定します。

    *   アクション：管理者とユーザーのポリシーを定義し、管理者ユーザーがすべてのデータを管理でき、ユーザーは自身のレコードにのみアクセスできるようにします。
    *   参照：PRDセクション4（ユーザー認証とロール管理）およびQ&A（ユーザーロールと権限）
    *   検証：管理者と一般ユーザーとしてログインしてロール権限をテストします。

3.  ステップ14：CSVレポートをエクスポートするためのサーバーレスAPI（必要に応じてSupabase Edge Functions経由）を作成します。

    *   ファイル：Supabase関数にファイルを作成（例：Supabaseプロジェクト関数ディレクトリ内の`export-report.js`）
    *   参照：PRDセクション4（レポートとデータエクスポート）
    *   検証：関数をトリガーしてCSVファイルを生成しダウンロードし、データのフォーマットが正しいことを確認します。

4.  ステップ15：サブスクリプションイベントを処理するためにSupabaseエッジ関数内にStripeウェブフックを統合します。

    *   ファイル：`/supabase/functions/stripe-webhook.js`
    *   参照：PRDセクション4（Stripeを介した支払い統合）
    *   アクション：Stripeシークレットキーを安全に保存して使用します。ウェブフックを設定してSupabaseデータベースのサブスクリプションステータスを更新します。
    *   検証：Stripeのテストイベントを使用してウェブフックの受信と処理を確認します。

フェーズ4：統合

1.  ステップ16：フロントエンドの認証と日々の学習入力ページをSupabaseバックエンドに接続します。

    *   ファイル：`/frontend/services/supabaseClient.ts`のAPIコールを更新
    *   アクション：フロントエンドページでSupabase JavaScriptクライアントを利用してリアルタイムでデータをフェッチおよび更新します。
    *   参照：PRDセクション3（ユーザーフロー）およびコア機能（日々の学習入力、ダッシュボード）
    *   検証：ログインしてエントリーを追加し、Supabaseダッシュボードで新しいデータを確認します。

2.  ステップ17：Stripe APIコールとウェブフックレスポンスをフロントエンドのサブスクリプションステータス更新と統合します。

    *   ファイル：`/frontend/services/subscription.ts`を更新
    *   参照：PRDセクション4（支払いとサブスクリプション）およびQ&A（Stripe統合）
    *   検証：サブスクリプション状態の変更をシミュレートし、UIが現在のサブスクリプションステータスを反映することを確認します。

3.  ステップ18：マークダウンエディタとダッシュボードをリアルタイムでデータを更新および表示するようにリンクします（Supabaseサブスクリプションを使用）。

    *   ファイル：`/frontend/pages/daily-entry.tsx`と`/frontend/pages/dashboard.tsx`の関連コンポーネントを更新
    *   アクション：チャートとログを自動更新するためにSupabaseからリアルタイムデータリスナーを実装します。
    *   検証：複数のエントリーを作成し、手動リロードなしでダッシュボードが更新されることを確認します。

フェーズ5：デプロイメント

1.  ステップ19：Next.jsフロントエンドをVercelにデプロイします。

    *   アクション：GitHubリポジトリをVercelに接続し、`main`ブランチからデプロイします。`.env`ファイルのキーを使用してVercelで環境変数を設定します。
    *   参照：PRDセクション5（非機能要件 – パフォーマンス）および技術スタック（フロントエンドデプロイメント）
    *   検証：デプロイされたURLを開き、Webアプリが正しい設定で読み込まれることを確認します。

2.  ステップ20：Supabaseバックエンド（データベース、認証、ストレージ、サーバーレス関数を含む）をデプロイします。

    *   アクション：Supabaseプロジェクトが適切なAPIキーとセキュリティ設定を備えた本番モードでセットアップされていることを確認します。
    *   参照：PRDセクション5（バックエンドとストレージ）
    *   検証：ログインして機能を使用してエンドツーエンドテストを実行し、バックエンドの接続を確認します。

3.  ステップ21：本番環境用のStripeのライブキーとウェブフックを設定します。

    *   アクション：SupabaseとVercelの両方の環境設定をライブStripe認証情報で更新します。
    *   参照：PRDセクション4（Stripe統合）およびQ&A（価格設定とサブスクリプションモデル）
    *   検証：テストのライブ取引を処理して、シームレスな支払い処理を確認します。

フェーズ6：ポストローンチ

1.  ステップ22：フロントエンドとSupabaseの両方のモニタリングとログ記録をセットアップします。

    *   アクション：VercelアナリティクスとSupabaseログを設定します。APIエラーやパフォーマンスの遅延のアラートを設定します。
    *   参照：PRDセクション6（非機能要件 – パフォーマンスとセキュリティ）
    *   検証：エラーをシミュレート（またはテストツールを使用）して、アラートが適切にトリガーされログに記録されることを確認します。

2.  ステップ23：Supabaseデータベースとストレージの定期的なバックアップをスケジュールします。

    *   アクション：Supabaseの自動バックアップ機能を使用するか、`pg_dump`を毎日実行するcronジョブを設定します。
    *   参照：PRDセクション7（制約と前提条件）およびQ&A（データセキュリティ）
    *   検証：バックアップログを確認し、テスト環境でバックアップからの復元を試みます。

3.  ステップ24：UI/UXと機能に関するフィードバックを収集するために、ターゲットユーザー（学生と教育者）の小グループでユーザビリティテストを計画しスケジュールします。

    *   アクション：初期ローンチ後にアンケートと直接のテストセッションを使用します。
    *   参照：PRDセクション1（プロジェクト概要）およびQ&A（ユーザーフィードバック）
    *   検証：将来のイテレーションのためにフィードバックを収集し分析します。

この計画は、StudyTracker Proがすべての要件を満たし、スムーズで安全で豊かなユーザーエクスペリエンスを提供することを確実にするために、すべてのフェーズと個々のステップを明示的なファイルパス、テスト手順、およびドキュメント参照とともに概説しています。
